# Plugin activation in Amethyst saved snapshots

Amethyst retains ordinary plugin names in `loadorder.txt` as position memory after their mod is disabled. Their absence from `plugins.txt` means they are inactive. An order entry alone must not activate a plugin, classify it as an implicit master, or make a missing source block connection.

houseCARL reads ordinary activation from starred entries in the captured `plugins.txt`. It applies that state to the saved ordering and includes explicitly active names missing from `loadorder.txt`, so a missing source for such a plugin still refuses. Unstarred entries and ordinary order-only entries are inactive. The reader never edits either input file.

The five Skyrim SE base/DLC master names remain engine-forced. Installed entries from the captured `Skyrim.ccc` supply the additional implicit plugin names; arbitrary order-only `.esm` or `.esl` files do not. Installed implicit entries are reported in composition even when absent from both explicit profile files. Explicitly inactive lines cannot disable an engine-forced plugin. Missing optional forced sources retain the existing incomplete-coverage warning rather than becoming ordinary active-source errors.

These rules follow Amethyst's [`sync.py`](https://github.com/ChrisDKN/Amethyst-Mod-Manager/blob/0b4e2899e702320f3e9c7ed5fa81f973c4d16330/src/Utils/plugins/sync.py), Skyrim SE game definition and plugin-state writer. The fixed master names and `.ccc` mechanism are also implemented in [libloadorder](https://github.com/Ortham/libloadorder/blob/master/src/game_settings.rs).

## Archive activation

The pinned native filegraph ranks managed archive contenders by saved plugin order and mod priority. It does not apply `plugins.txt` activation to those contenders. Its winner IDs describe the saved filegraph, so they remain intact in the capture. At the engine view, houseCARL filters plugin-bound archive contenders through the same resolved activation set used for plugin paths and status. The remaining contenders keep their saved precedence; removing an inactive winner exposes the next eligible saved contender. No staging rescan or routing recalculation is introduced.

Archives explicitly named in the effective INI lists remain eligible independently of plugin activation. Each archive-list key uses `SkyrimCustom.ini` when present, falling back to `Skyrim.ini`; an explicit empty Custom value clears the inherited list. Unbound archive behavior is unchanged. The same eligibility predicate governs asset lookup, archive listings, active-provider status and asset enumeration. Explicit named-source lookup can still read a saved inactive donor; donor availability does not activate it.

Vanilla plugin-bound archives use the same resolved plugin sequence. Freshness checks still cover the profile files, effective INIs, `.ccc` and observed sources. Toggling or changing inputs during a read therefore refuses the capture rather than silently switching activation state.

## Regression fixtures

The activation regressions exercise schema 9/rules 13 and schema 10/rules 14, 15, 18 and 19. The additional rules-19 activation fixture is generated by `scripts/probes/build_amethyst_snapshot_fixture.py --scenario activation` with the existing pinned producer. It records a higher-priority `Fixture.bsa` and a lower-priority `Active.bsa` containing the same member. With `Fixture.esp` inactive, only the saved `Active.bsa` contender remains eligible. This tests archive fallback using producer-generated candidates and precedence rather than hand-written winner rows.
