# Linux Papyrus tools

The Linux package builds Caprica and Champollion from pinned source commits with the pinned vcpkg registry baseline in [`scripts/native-tools.lock.json`](../scripts/native-tools.lock.json) and [`scripts/vcpkg-linux-tools.json`](../scripts/vcpkg-linux-tools.json). The build uses Clang, CMake, Ninja, and static vcpkg libraries. It stores the two source archives, their license files, the vcpkg dependency notices, and exact build metadata beside the binaries under `dist/linux-tools`; the package builder includes only entries named and hash-verified by that metadata.

Run `scripts/build-linux-tools.py` to reproduce the native builds. The host needs Git, Python 3.12+, CMake, Ninja, Clang/Clang++, Clang's dependency scanner, curl, zip, unzip, and tar. On Ubuntu 24.04, install `clang-tools-18` alongside `clang` to provide `clang-scan-deps`; otherwise CMake's thread check can fail while attempting to run the missing scanner. The script downloads only the pinned commits and the dependency recipes selected by the vcpkg baseline. It does not install host packages.

The pinned Caprica source has a Linux case mismatch in its top-level CMake file: it adds `Caprica/` while the checked-in directory is `caprica/`. The build creates a temporary `Caprica -> caprica` symlink in the disposable checkout; the archived upstream source remains unchanged, and the recipe carrying this correction is shipped with the package.

The pinned `caprica/common/FSUtils.cpp` also uses `std::replace`, `std::transform`, and `std::back_inserter` without directly including their standard headers. Compilation fails with Ubuntu 24.04's Clang 18 and libstdc++ 13. The recipe adds `<algorithm>` and `<iterator>` in the disposable checkout, verifies that the expected include block matches exactly once, and records the correction in the build metadata.

The same pinned source writes PEX object lengths in host byte order and excludes the length field itself. Skyrim output needs big-endian lengths including that four-byte field; otherwise Mutagen rejects the actual compiled file and the managed compile tool refuses publication. The recipe patches `caprica/pex/PexWriter.h` in the disposable checkout before compilation, verifies that the original statement matches exactly once, and records this correction in `native-build-info.json`. The original source archive and the exact patched build recipe both ship. An externally supplied, uncorrected Caprica binary may still fail strict PEX validation.

`PapyrusCompileEndToEndTests` runs the real native binary from `dist/linux-tools/caprica`, or an explicitly supplied `HOUSECARL_TEST_CAPRICA` path. Its five cases use authored, redistributable scripts and flags with no game installation: valid and broken scripts, a separate source import plus its missing-dependency refusal, changed-function recompilation, and byte-preservation after a failed recompile. Generated PEX objects and return instructions are read with Mutagen. Caprica diagnostics retain the filename, starting line/column and message from its range-based format. Only an absent compiler or a non-Linux host causes an explicit skip; a present but broken binary fails.

The smoke test compiles a synthetic Skyrim Papyrus script with Caprica, then decompiles its PEX with Champollion. It verifies the native executables and CLI integration. Game behavior and compatibility with individual mods require separate checks. The package assembler requires build metadata for Ubuntu 24.04's glibc 2.39 exactly; an Arch-derived build is useful for development but cannot produce the release archive. Clean Ubuntu 24.04 acceptance and a selected-Proton run remain separate release checks.
